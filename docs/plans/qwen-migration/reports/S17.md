## Note per le sezioni successive

- `QwenMoE` è interno a `TurboFieldfare` (`Kernels/Qwen/QwenMoE.swift`): decode = chiamata diretta dei tre `encode*` (`encodeGateUpSilu` → `encodeDown` → `encodeResidual` con `slots = 8`); prefill = `encodePrefill` (ciclo per token, serializzato dentro un solo command buffer; gli scratch mono-token `acts`/`sharedActs`/`routedOut`/`sharedOut` sono riallineati a ogni token).
- Scratch richiesti da `encodePrefill`: `acts` 8·I·2 B, `sharedActs` I·2 B, `routedOut` 8·H·2 B, `sharedOut` H·2 B; `x`/`residual`/`y` contigui per token con stride H·2 byte, `routingW` stride 8·4 byte (FP32), `sg` stride 2 byte (FP16, [T] nel prefill).
- L'argument buffer dei blob (`makeBlobsArgumentBuffer`) va ricostruito quando i buffer degli slot cambiano: in integrazione con `PreadExpertStreamer` basta ri-chiamarlo per token se lo streamer ruota i buffer, è un'allocazione di poche decine di byte.
- Lo shared expert usa lo stesso layout C5 dei routed: in S18/S19 il blob dello shared expert può stare resident in una `MTLBuffer` unica, con `makeBlobsArgumentBuffer(blobs: [shared], slots: 1)`.
- Gli offset del kernel sono passati come `QwenExpertOffsets` (9 × UInt32) via `setBytes`; `QwenMoE.expertOffsets(hidden:inter:)` li calcola dalle dimensioni, quindi varanti con inter/hidden diversi funzionano senza nuove costanti.
