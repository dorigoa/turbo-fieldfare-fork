## Valori misurati o fissati
- `QwenToolCallParser.maximumBytes = 256 * 1024` (come Gemma);超限 del corpo
  del blocco in streaming → `.oversized`.
- Errori: `QwenToolCallParserError.malformed | unknownTool | oversized`
  (enum proprio, non si riusa quello Gemma). Corpo del blocco in streaming
  oltre il limite → `.oversized`.
- Valore parametro: si prova `JSONValue` via `JSONDecoder` su tutto il testo
  dopo un solo `\n` iniziale e uno finale rimossi; JSON valido (inclusi
  `null` e stringhe tra virgolette) → valore JSON, altrimenti stringa.
- Il separatore `\n\n` dopo `</think>` viene inghiottito; un solo `\n` resta
  contenuto (deterministico).

## Note per le sezioni successive
- API: `QwenAssistantDecoder(allowedTools:insideReasoning:idGenerator:)`,
  `consume(_:) throws -> [StructuredAssistantEvent]`,
  `finish() throws -> [StructuredAssistantEvent]` (flush finale: restituisce
  il tail trattenuto), `onReasoning` callback, `hasToolCalls`. Il ragionamento
  non passa mai dagli eventi (D11); l'enum pubblico non è stato toccato.
- Il costruttore del decoder prende `insideReasoning`: `true` se il prompt
  finisce `<think>\n`, `false` se finisce `</think>\n\n` (3.6). S19/S21/passi
  CLI/server devono passarlo coerentemente col prompt renderizzato.
- `QwenToolCallParser.callOpen`/`callClose` contengono i marker speciali
  (scritti come escape `\u{3C}`); usarli per costruire testo nei test.
- Il parser accetta blocchi con o senza i marker di contorno (li toglie se
  presenti), quindi S21 può passargli il solo interno o il blocco intero.
