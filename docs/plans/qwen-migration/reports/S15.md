## Valori misurati o fissati

- Errori relativi massimi (CPU ref; tolleranze C8 `fp16Reduction = 5e-3`, `quantInt4 = 1.5e-3`):
  scan `o`: 2.6e-4 … 3.8e-4; scan stato FP32: ≤ 1.8e-7;
  C8 dopo 256 passi: stato 1.19e-7 (≤ 1e-4, margine ampio);
  out_proj: 4.1e-4 (vh4/m256), 4.9e-4 (vh32/m2048).
- Continuità: relErr A e B = 3.14e-4 identici; uscite A/B `maxAbsDiff == 0`; stato finale
  bit-identico → la continuità prefill↔decode è **bit-esatta** anche per la ricorrenza.
- Layout fissati: stato D5 `[32][128][128]` FP32 colonna-maggiore (colonna = `keyDim` float
  contigui), riusato **in place**; `o` compatto `[tokens][32·128=4096]` FP16, pronto per
  `encodeGatedPerHead`; beta/decay FP32 `[tokens][32]` (S14); v letto a row-stride 8192
  tramite `vRowStride` (test: slice compatta con stride = 4096).
- Costretti dal kernel: `keyDim` multiplo di 32 ≤ 256 (8 righe per lane al massimo, 4 a 128),
  `valueHeads % keyHeads == 0` (mappa 3.5 kh = j/2).
- Funzioni Metal: `qwen_deltanet_scan` (SIMD-group per (testa, colonna), 32 thread/gruppo),
  `qwen_add_f16` (256).

## Note per le sezioni successive

- S18/S19 (runner): `encodeScan` accetta offset in byte su tutti i buffer → il runner può
  indicizzare lo slice di un token nel buffer conv da 8192 senza copie; lo stesso buffer
  stato fa da input e output (in place). Continuità già bit-esatta: nessun lavoro extra.
- Lo stato di un layer lineare è 32·128·128·4 B = 2.097 MB (cache D5 ×24 layer ≈ 50 MB FP32):
  da dimensionare in S18.
- Per prefill con `rows > 1` in `encodeGatedPerHead` l'uscita `o` è già compatta [tokens][4096]:
  nessun re-pack; i test d'uscita usano `rows = 1` (decode), la variante multi-riga va
  verificata in S18/S19 con il runner.
- `DequantInt4GEMV` per out_proj: m = 2048 righe di peso, n = 4096; il residuo è la somma
  FP16 di `qwen_add_f16` (in-place safe, `out == a` ok).
