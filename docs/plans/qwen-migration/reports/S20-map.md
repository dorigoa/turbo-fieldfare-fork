## GEMM prefill — decisione: GEMM
- `MPPPrefillInt4QMM.encode(commandBuffer:weights:weightsOffset:scales:scalesOffset:biases:biasesOffset:x:xOffset:y:yOffset:m:n:k:) -> PathMetadata` (Kernels/TensorCore/MPPPrefillInt4QMM.swift:120). Pesi Qwen 4-bit = affine MLX gruppo 64 (Quantization.groupSize, Infrastructure/ModelIO/Quantization.swift:5): **stesso layout** già servito per Gemma → `weights=v.buffer, weightsOffset=v.offset, scales=v.buffer, scalesOffset=v.scaleOffset, biases=v.buffer, biasesOffset=v.biasOffset` (TensorView, ModelTypes.swift:221). `m = T`, `n` uscite, `k` ingressi; x/y [T][n] FP16 row-major.
- Vincoli: k % 64 == 0 (sempre: 2048/4096/512); path Apple10 veloce se `m ≥ 64` e k % 128 == 0 (:140-141); altrimenti path F16 di controllo (tileM 64 arrotonda m; corretto per m ≥ 1); offset multipli di 2 B (veri nei TensorView, come per il GEMV di S19). `PathMetadata.path == .fallback` → niente GEMM: ripiegare su GEMV per token (guardia, non attesa).
- Proiezioni 4-bit col GEMM: in_proj_qkv (n8192×k2048), in_proj_z (4096×2048), in_proj_a/b (32×2048), out_proj (2048×4096), q (8192×2048), k/v (512×2048), o (2048×4096). lm_head (248320×2048) solo sull'ultima riga: `DequantInt4GEMV` m=1 come S19 (o GEMM m=1, equivalente).
- Router 8-bit: `MPPPrefillInt8QMM.encode` (MPPPrefillInt8QMM.swift:61), stessa firma, un solo path F16, k % 64, **weightsOffset % 4 == 0** (:74, :44): verifica runtime, altrimenti T× `DequantInt8GEMV` (come S19). m = T.
